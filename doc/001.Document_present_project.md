## Mode

This is an application that changes the traditional approach of creating one CV for each job position into an unlimited number of customizable CVs.

It is a simple web and mobile application designed to reduce stress and help users organize their CVs without relying on AI to arbitrarily generate new CVs containing irrelevant or inaccurate information.

The application has a database containing all the user's skills, projects, and certificates, which can be imported from JSON files or URLs. Each skill, project, and certificate is stored as a separate information block that users can select and add whenever needed, based on the requirements of the position and the recruiter's expectations.

# CareerForge AI — Database Architecture

## 1. Database Overview

| Element | Description |
|---|---|
| Database | PostgreSQL |
| Architecture | Relational database |
| Main objective | Store professional information as reusable blocks |
| Main records | Users, profiles, projects, skills, certificates, experiences and CVs |
| CV generation | Manual selection and composition of existing information |
| Data imports | GitHub API, JSON files, external URLs and manual entry |
| CV history | Versioning and content snapshots |
| Optional technology | JSONB for metadata and historical snapshots |

## 2. Main Database Modules

| Module | Responsibility | Main Tables |
|---|---|---|
| User Management | Manage accounts and authentication | `users`, `profiles` |
| Professional Profile | Store personal and professional information | `profiles`, `educations`, `experiences`, `languages` |
| Projects | Store reusable project information | `projects`, `project_skills`, `project_links` |
| Skills | Organize technical and professional skills | `skills`, `skill_categories`, `user_skills` |
| Certificates | Store certifications and verification information | `certificates`, `certificate_skills` |
| CV Management | Create and manage customized CVs | `cvs`, `cv_projects`, `cv_skills`, `cv_certificates` |
| Import Management | Track imported information and its origin | `import_sources`, `import_jobs`, `imported_records` |
| CV Versioning | Preserve previous CV content | `cv_versions` |
| Job Applications | Track applications, if included | `job_offers`, `applications` |

## 3. Database Table Structure

### A. Users and Professional Profiles

**Table: `users`**

| Column | PostgreSQL Type | Description |
|---|---|---|
| `id` | UUID | Unique user identifier |
| `email` | VARCHAR(255) | Account email |
| `password_hash` | VARCHAR(255) | Hashed account password |
| `created_at` | TIMESTAMPTZ | Account creation date |
| `updated_at` | TIMESTAMPTZ | Last modification date |

**Table: `profiles`**

| Column | PostgreSQL Type | Description |
|---|---|---|
| `id` | UUID | Profile identifier |
| `user_id` | UUID | Owner reference |
| `first_name` | VARCHAR(100) | First name |
| `last_name` | VARCHAR(100) | Last name |
| `professional_title` | VARCHAR(150) | Professional headline |
| `summary` | TEXT | Professional summary |
| `phone` | VARCHAR(30) | Contact number |
| `location` | VARCHAR(150) | Location |
| `linkedin_url` | TEXT | LinkedIn profile |
| `website_url` | TEXT | Personal website |

| Relationship | Description |
|---|---|
| `users` → `profiles` | One user has one main professional profile |
| `profiles` → `cvs` | The profile can be reused across multiple CVs |

| Column | PostgreSQL Type | Description |
|---|---|---|

| Column | PostgreSQL Type | Description |

| Relationship | Description |
|---|---|
| `users` → `cvs` | One user can create multiple CVs |
| `cvs` → `cv_projects` | A CV can contain multiple projects |
| `cvs` → `cv_skills` | A CV can contain multiple skills |
| `cvs` → `cv_certificates` | A CV can contain multiple certificates |
| `cvs` → `cv_experiences` | A CV can contain multiple experiences |
| `cvs` → `cv_educations` | A CV can contain multiple education records |

| Design Principle | Description |
|---|---|
| Reusability | The same project can appear in several CVs |
| No duplication | Selecting a project does not create another project record |
| Customization | A project description can be adapted for a specific CV |
| Manual control | The user decides which information blocks are included |
| Ordering | Selected blocks can be reordered within the CV |

The professional information library stores information once and allows it to be reused across different CV compositions.

| Information Type | Example Quantity |
|---|---:|
| Projects | 12 |
| Skills | 28 |
| Certificates | 9 |

### Example CV Compositions

| CV | Selected Projects | Selected Skills |
|---|---|---|
| Cybersecurity Engineer | Wazuh ML IDS, Zero-Trust SOC | Linux, SIEM, Network Security |
| DevSecOps Engineer | Kubernetes Lab, CI/CD Pipeline | Docker, Kubernetes, Terraform |
| Backend Developer | Kidora Backend, Redis Project | Java, Spring Boot, PostgreSQL |

| Principle | Description |
|---|---|
| Centralized information | All professional information is stored in one library |
| Multiple CVs | Users can create several targeted CVs |
| Shared records | CVs reuse the same original project, skill and certificate records |
| Independent composition | Each CV contains its own selection and ordering of information |

## 5. Import and Source Management

The application supports several methods for importing professional information.

### Import Methods

| Import Method | Information Imported | Example |
|---|---|---|
| GitHub API | Repositories, README files, languages and project URLs | GitHub account |
| JSON file | Projects, skills and certificates | Portfolio backup |
| External URL | Certificate information and verification links | Credly certificate |
| Manual entry | Information that cannot be imported automatically | Personal project |
