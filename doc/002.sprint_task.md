### Phase 5 — AI Matching and Recommendation Engine

**Objective:** Analyze job descriptions against the user's existing professional information and recommend relevant information blocks.

**Important design principle:** AI must recommend existing information, not invent projects, skills, experience or certificates. The user retains control over every selection.

| Task | Description | Expected Result |
|---|---|---|
| 5.1 | Define the job description data structure | Structured job requirements |
| 5.2 | Implement a job description input interface | User can paste a job description |
| 5.3 | Extract relevant keywords from job descriptions | Job requirements identified |
| 5.4 | Identify technical skills and technologies | Structured skill requirements |
| 5.5 | Identify experience and project requirements | Structured professional requirements |
| 5.6 | Compare required skills with existing user skills | Skill matching results |
| 5.7 | Compare job requirements with project descriptions and evidence | Relevant projects identified |
| 5.8 | Compare certification requirements with existing certificates | Relevant certificates identified |
| 5.9 | Implement a matching score based on defined criteria | Transparent relevance score |
| 5.10 | Generate recommendations for relevant information blocks | Suggested projects, skills and certificates |
| 5.11 | Display missing or weakly supported requirements | Identified information gaps |
| 5.12 | Allow users to accept or reject recommendations | Manual selection control |
| 5.13 | Save job matching results | Historical matching records |
| 5.14 | Test matching accuracy using sample job descriptions | Evaluated recommendation quality |

**Deliverables:**

- Job description analyzer.
- Skill and project matching engine.
- Certificate recommendations.
- Transparent matching score.
- Missing-skill and evidence analysis.
- User-controlled recommendations.

**Completion criteria:** A user can paste a job description and receive recommendations based only on existing information in their professional library.

**Technical note:** The first version can use deterministic keyword matching and weighted scoring. An LLM can optionally improve requirement extraction, but it must not create or modify the user's professional facts.

### 7.5 MVP Scope and Optional Features

| Feature | MVP Requirement | Later Improvement |
|---|---|---|
| Authentication | Email/password and secure sessions | Additional identity providers |
| GitHub integration | Repository import and review | Automatic scheduled synchronization |
| Certificates | Manual registration and verification links | More automated certificate extraction |
| Projects | Manual and GitHub-based management | Additional portfolio integrations |
| Skills | Manual management and project associations | Advanced skill analysis |
| AI matching | Basic matching and recommendations | Semantic matching and improved extraction |
| CV editor | Manual selection and ordering | Additional templates and layout customization |
| PDF export | Standard PDF generation | More advanced export options |
| Job tracking | Basic status management | Notifications and analytics |
| Monitoring | Logs and health checks | Advanced monitoring dashboards |

**Final development principle:** Build the application in layers. First establish a reliable professional information database, then implement manual CV composition, and finally add intelligent recommendations. AI should improve the selection process without taking control of the user's professional information.
